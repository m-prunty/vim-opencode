1. INTRODUCTION                                             *vim-opencode-introduction*

vim-opencode.vim is a Vim 9.1-native client for OpenCode. It speaks the OpenCode
V2 HTTP and SSE APIs and keeps its core independent of windows and buffers.
The UI is added in layers: prompt and context workflows first, then a split
panel, permissions and diff review.

This help file describes the current walking skeleton: configuration, command
dispatch, server discovery, transport, SSE events, context-aware prompts and
a split-panel transcript. Commands marked with a phase such as (P4) indicate
the implementation phase; commands without a phase marker are reserved.

==============================================================================
2. REQUIREMENTS                                             *vim-opencode-requirements*

- Vim 9.1 or newer.
- The |+job|, |+channel| and |+timers| features.
- The |+textprop|, |+popupwin|, |+diff| and |+quickfix| features for later
  phases.
- curl(1) on $PATH for HTTPS requests and server-sent events.

Run |:Opencode| health to check the current build.

3. COMMANDS                                                   *vim-opencode-commands*

                                                                 *:Opencode*
:Opencode [command] [arguments]
                        Execute an vim-opencode command. With no argument, show
                        the command summary. Command names and common
                        arguments are completed with <Tab>.

                        The command accepts a range. Later prompt commands use
                        it to scope context. A ! is reserved for debugging.

                                                        *vim-opencode-command-list*
help [doc]              Show the command summary. With "doc", open this help
                        file.
version                 Show the plugin and Vim versions.
health                  Run environment checks and list missing capabilities.
config [path]           Print the merged configuration as JSON. With a dotted
                        path such as "panel.height", print only that value.
config validate         Validate the active configuration.
server [action]         Manage discovery and the connection. Actions:
                          status      Show the active URL, version and state.
                          connect     Discover and connect, then subscribe.
                          disconnect  Close the stream and stop reconnecting.
                          start       Run the configured server_command.
                          stop        Stop a server started by this plugin.
session ...             List, create, open, rename, fork or delete conversations.
                        See |vim-opencode-sessions|.
prompt [text]           Send a prompt with @ placeholders. With no text, open
                        the ask input. A trailing ... opens ask with the text
                        before it as the initial value.
ask [text]              Open the ask input with optional initial text.
operator [text]         Set 'operatorfunc' and wait for a motion; the selected
                        range is sent with the text (default @this).
context ...             Inspect or clear captured context. (P2)
toggle                  Toggle the conversation panel. (P3)
open [target]           Open the input, output or panel window. (P3)
close [target]          Close a panel window. (P3)
permission ...          List, accept, deny or answer pending requests.
diff ...                Open, accept, reject or close the active edit diff.
review ...              List, add or clear review comments. Comments are
                        attached to the next prompt.
quickchat [instruction] Replace the current range with a focused assistant
                        response. The replacement is whole-line and undoable.
tab ...                 List, create, select or close persistent panel tabs.
quickchat               Replace the current range in place. (P7)
debug ...               Inspect plugin state. (P10)

                                                          *vim-opencode-discovery*
Server discovery tries, in order:

1. The configured |g:vim_opencode_config| server_url. A configured URL is
   authoritative; the plugin never starts a different server for it.
2. OpenCode background registrations in
   $XDG_STATE_HOME/opencode (or ~/.local/state/opencode):
   service.json and service-*.json, newest first. Each registration supplies
   a URL and optional password.
3. The configured server_command, followed by polling for up to five seconds.

Every candidate is probed with GET /api/info before it becomes current. The
SSE stream is then opened on GET /api/event. Lost streams reconnect with
exponential backoff until :Opencode server disconnect or Vim exits.

                                                           *vim-opencode-context*
Context placeholders are expanded in prompt and ask text before submission.
They are matched longest-first, so @buffers is not mistaken for @buffer.

  @this         The selected range, or the cursor location.
  @buffer       The current buffer path (or full text for a scratch buffer).
  @buffers      All listed file-backed buffers.
  @visible      The visible line range in every window.
  @quickfix     The quickfix list locations.
  @marks        Global marks A-Z.
  @diagnostics  Quickfix entries for the current buffer or selected range.

File-backed locations use OpenCode's path format:
  path:L12:C4-L18:C9
Linewise ranges omit the column numbers. If a placeholder has no value it is
left in the prompt unchanged. Diagnostics are quickfix-backed because Vim has
no vim.diagnostic equivalent; populate the quickfix list from your build,
grep, or lint workflow.

Prompt flow:

1. Capture the command range, visual marks, cursor, buffer and cwd.
2. Highlight the range, then expand placeholders.
3. Resolve the most recent non-archived root session for the cwd with
   GET /api/session?directory=...&order=desc&parentID=null.
4. POST /api/session/{id}/prompt with the rendered text.
5. On success clear the highlight. On failure restore the visual selection
   and leave the buffer unchanged.

The optional start command is polled for five seconds. Use
:Opencode server status to inspect the active URL, version and stream state.

                                                           *g:vim_opencode_config*
g:vim_opencode_config      Dictionary of user settings. It is validated at
                        startup. Invalid types, URLs or enum values abort
                        loading with an error naming the bad key.

                                                              *vim-opencode-config-keys*
server_url              Base URL of a running OpenCode server. Empty means
                        discover a server of start one with server_command.
server_command          String or list used to start OpenCode when a server is
                        not already running.
auto_start              Start or discover a server on first use.
directory               Directory scope sent to the server. Empty means the
                        current working directory.
request_timeout_ms      Timeout for ordinary HTTP requests.
stream_timeout_ms       Idle timeout for a streaming response.
connect_timeout_ms      Timeout for discovery and health probes.
reconnect_delay_ms      Initial SSE reconnect delay.
max_reconnect_delay_ms  Maximum SSE reconnect delay.
default_mappings        Install the normal-mode mappings from keymaps.
log_level               silent, error, warn, info or debug.
log_file                Optional file for log lines. Empty disables file logs.
keymaps                 Mapping targets used when default_mappings is true.
server                  username, password and extra HTTP headers.
context                 Limits and defaults for captured editor context.
panel                   Layout and render batching settings.
diff                    Edit review behavior.
gui                     Popups, borders and status bar settings.

                                                          *gui-config-keys*
gui.popup_border        rounded, single or none. Default rounded when
                         &ambiwidth is single, else single.
gui.popup_title         Show a title bar on popups.
gui.footer_hint         Show a hint footer on popups.
gui.preview_width       Width of the side preview popup.
gui.colors              Enable highlight-group-derived colors.
gui.default_position    right, horizontal or popup. Where :Opencode open
                         and :Opencode toggle place the panel; right (a
                         vertical split on the right) is the default.

5. EVENTS                                                         *vim-opencode-events*

The event bridge emits a User autocmd for every server-sent event:

>vim
autocmd User OpencodeEvent:session.status echo g:vim_opencode_event_type
<

The event type follows the colon. The decoded payload is available in
g:vim_opencode_event, and the type is also in g:vim_opencode_event_type. Events are
only emitted when a matching autocmd exists, so no message is printed for
unhandled types.

The stream currently emits the V2 types, including:

  OpencodeEvent:server.connected
  OpencodeEvent:session.status
  OpencodeEvent:message.updated
  OpencodeEvent:permission.asked
  OpencodeEvent:question.asked

The plugin also emits local events:

  OpencodeEvent:server.disconnected  Stream lost; before a reconnect attempt.
  OpencodeEvent:prompt.sent          Prompt POST succeeded; data.sessionID.
  OpencodeEvent:prompt.failed        Prompt failed; data.message.
  OpencodeEvent:session.opened       A session was attached to the panel.
  OpencodeEvent:session.created      A new session was created; data.sessionID.
  OpencodeEvent:session.renamed      A session title changed; data.title.
  OpencodeEvent:session.deleted      A session was deleted; data.sessionID.
  OpencodeEvent:session.forked       A session was forked; data.newSessionID.
  OpencodeEvent:permission.pending  A permission or question needs attention.
  OpencodeEvent:permission.replied  A permission response was accepted.
  OpencodeEvent:question.answered   A question response was accepted.
  OpencodeEvent:diff.pending        A single-file edit is ready for review.
  OpencodeEvent:diff.accepted       A proposed edit was written to disk.
  OpencodeEvent:diff.rejected       A proposed edit was discarded.
  OpencodeEvent:review.pending      A review comment was created.

6. PANEL                                                       *vim-opencode-panel*

The split panel shows a streaming transcript of the conversation above an
input buffer. Open it with |:Opencode| toggle, |:Opencode| open or
|:Opencode| open panel.

                                                              *vim-opencode-panel-layout*
The panel is a horizontal split. The top window holds the read-only
transcript; the bottom window holds a three-line input buffer. The panel
respects |g:vim_opencode_config| panel settings (height, position, debounce_ms).

                                                              *vim-opencode-panel-commands*
:Opencode toggle          Show or hide the whole panel.
:Opencode open            Open the full panel (transcript + input).
:Opencode open input      Open only the input window.
:Opencode open output     Open only the transcript window.
:Opencode open panel      Open the full panel.
:Opencode close           Close the whole panel.
:Opencode close input     Close only the input window.
:Opencode close output    Close only the transcript window.
:Opencode close panel     Close the whole panel.

                                                              *vim-opencode-panel-mappings*
In the transcript window:

  <CR>                  Jump to the file location under the cursor.
  q                     Close the panel.
  ]m                    Jump to the next message start.
  [m                    Jump to the previous message start.
  ]u                    Jump to the next user message.
  [u                    Jump to the previous user message.

In the input window:

  <CR>                  Submit the draft as a prompt.
  <C-p>                 Previous draft from history.
  <C-n>                 Next draft from history.

                                                              *vim-opencode-panel-streaming*
Server-sent events (session.text.delta, session.tool.*, session.step.*) are
applied to the transcript model and rendered on a debounce timer, so the
editor never blocks while tokens stream in. Scrolling up is preserved: new
content only jumps to the bottom when the view was already at the bottom.

7. GUI                                                     *vim-opencode-gui*

The GUI layer adds styled popups, an interactive command palette, preview
windows and a show/peek key, modeled on fzf.vim. All colors are derived from
Vim highlight groups (never hard-coded ANSI) and honor |termguicolors|.

                                                               *vim-opencode-palette*
:Opencode palette               Open the interactive command palette.
                                Lists every implemented :Opencode command plus
                                direct sub-actions (sessions, models, agents,
                                server, permissions, diff, tabs). Navigate with
                                j/k or <Up>/<Down>, filter with /, run with
                                <Enter>, preview with <C-P>, quit with <C-Q>.

                                                               *vim-opencode-pickers*
Styled pickers (replacing plain :echomsg / inputlist() lists) are used for
:Opencode model pick, :Opencode agent pick, :Opencode command pick,
:Opencode session pick and :Opencode permission list. Each shows a bordered
titled popup with a footer hint (Enter pick | C-P preview | C-Q quit).

                                                               *vim-opencode-preview*
<C-P> in a picker or the palette opens a side preview popup showing context
for the highlighted entry (kind, name, description, usage).

                                                               *vim-opencode-peek*
<C-O> (show/peek) runs the highlighted entry's action in the editing window
without closing the popup, so you can inspect a session, model or command
and keep browsing.

                                                               *vim-opencode-panel-scroll*
Scrolling works in the transcript/output window and in popups:
<C-e>/<C-y> scroll one line, <C-d>/<C-u> and <PageDown>/<PageUp> scroll a
page.

                                                               *vim-opencode-panel-right*
:Opencode open and :Opencode toggle open the panel to the right of the
screen (vertical split) by default. Set gui.default_position to 'horizontal'
to use panel.position, or 'popup' for a floating window.

All popup borders use |gui.popup_border| ('rounded' by default when
|&ambiwidth| is single, else 'single'). Popups fall back to inputlist()
when +popupwin is unavailable.

8. SESSIONS                                                   *vim-opencode-sessions*

Sessions are listed per working directory. The plugin keeps a small cache so
commands can refer to a session by its full id, a unique id prefix, or the
number shown by |:Opencode| session list.

                                                              *vim-opencode-session-commands*
:Opencode session                 List sessions for the current directory.
:Opencode session list            Same as above.
:Opencode session pick            Choose a session from a popup menu.
:Opencode session new [title]     Create a session and open it in the panel.
:Opencode session open [id]       Open a session. With no id, follow the most
                                  recently updated session again.
:Opencode session rename [id] [title]
                                  Rename a session. The title is prompted for
                                  when omitted.
:Opencode session delete [id]     Delete a session after confirmation.
:Opencode session delete! [id]    Delete without prompting.
:Opencode session fork [id]       Fork a session. With no id, fork the current
                                  session.
:Opencode session current         Print the session attached to the panel.

Opening a session pins it: reconnecting or reopening the panel keeps that
session instead of jumping back to the most recently updated one. Use
:Opencode session open with no id to follow the most recent session again.

The info header at the top of the transcript shows the active server, working
directory, session and model. It updates as events arrive.

9. FUNCTIONS                                                 *vim-opencode-functions*

not need to parse command strings. Names are finalized with the phase that
